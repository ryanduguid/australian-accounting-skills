# Native accounting skill tooling

This crate is the first local Rust porting slice for the repository tooling.
It derives the coverage matrix without a Python runtime. It needs no network
and does not assess whether a source or accounting conclusion is correct.

```sh
cargo build --locked --release
accounting-skills build-coverage --root /path/to/checkout --check
accounting-skills build-coverage --root /path/to/checkout --write
```

The current directory is the default root. A root operand beginning with a dash
needs an explicit path, such as `./--check`. `--write` takes precedence over
`--check`, as in the Python command. Success prints the matrix unless writing,
which prints `wrote coverage.json`. A stale check exits 2. Processing and
argument errors exit 1 with a diagnostic instead of a Python traceback or
argparse usage. Help text is not yet ported.

The schema, field order, note text, source-date distinctions, card deduplication,
quoted test mentions and platform newline conventions preserve the Python
builder. Native stdout is always UTF-8. Python 3.14 may use its local code page
when piped on Windows; CLI byte comparisons use its explicit `-X utf8` mode.
The original note deliberately still names its Python producer so
the generated bytes remain comparable. Human review dates are never advanced.

The source schema requires date and URL fields to be strings and `sources` to
be an array. This candidate refuses malformed types rather than reproducing
Python's conversion of arbitrary values into provenance strings. Non-Unicode
filenames are refused. Unicode equivalence is sampled, not exhaustive.

Original scripts, consumer commands and CI remain in place. Source refresh,
validation, trial preparation and sweep outcomes are still Python and remain
unfinished porting work. This crate is not a release or consumer cutover.
